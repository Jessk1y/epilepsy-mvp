# ЭпиАссистент — приложение MVP (Г1 ЭЭГ + Г2 МРТ)

Второе мнение для врача: вероятность эпилепсии по рутинной ЭЭГ (Г1) и поиск очагов ФКД на МРТ (Г2).
Интерфейс — «Пульт», тёмная рабочая станция (раздел «Интерфейс» ниже). План и контракты — [PLAN.md](PLAN.md),
снимки экранов — [docs/screens/](docs/screens/).

**Результат программы — второе мнение, решение принимает врач.** Модель ЭЭГ оценивает запись целиком и не указывает места разрядов.

## Запуск в демо-режиме (ноутбук, без моделей и видеокарты)

```bash
py -m pip install -r app/requirements.txt      # один раз: fastapi, uvicorn, numpy, scipy, nibabel, pytest
py app/run.py --demo                           # затем открыть http://127.0.0.1:8000
```

В демо-режиме всё, кроме нейросетей, настоящее: чтение EDF, подготовка сигнала, проверка входа, порог клиники, просмотр сигнала и
срезов, отчёт. Данные — синтетические, создаются на лету и помечены «ДЕМО»:

- **ЭЭГ** — шум со спектром 1/f, альфа-ритм, моргания, помехи (`epiapp/g1/synth.py`), записанные в настоящий EDF. Оценку даёт
  демо-модель (простая формула, клинического смысла нет). Можно загрузить и свой EDF: подготовка и проверка будут настоящими.
- **МРТ** — схема головы из эллипсоидов и сглаженного шума (`epiapp/g2/phantom.py`), не снимок человека. Свои снимки в демо не принимаются.

Данные TUH и других наборов в демо не используются, поэтому вопросов лицензии нет. Рабочий каталог — `app/var/` (в `.gitignore`).

## Запуск в боевом режиме (рабочая машина: Ubuntu, RTX A5000)

```bash
source ~/venvs/tuep/bin/activate
cd ~/epilepsy-mvp && git pull
pip install fastapi uvicorn nibabel            # в venv уже есть torch 2.14 + cu130, transformers, timm, einops, numpy, scipy

export EPI_VAR_DIR=~/data/epiapp_var           # загруженные записи, база, отчёты — вне репозитория
export EPI_CLINIC="Название клиники"
export EPI_G1_MODEL=reve_dino                  # или tuep_pair (см. ниже)
export EPI_REVE_DIR=~/data/weights/h1-reve-v4  EPI_DINO_DIR=~/data/weights/h1-eegdino-v2
export HF_HUB_OFFLINE=1                        # основы REVE и EEG-DINO берутся из кэша Hugging Face (он уже есть после tuep_infer.py)
CUDA_VISIBLE_DEVICES=0 python app/run.py --real --port 8000
```

Сервер слушает только `127.0.0.1`. С ноутбука — проброс порта по SSH, затем открыть `http://127.0.0.1:8000`:

```bash
ssh -N -L 8000:127.0.0.1:8000 <пользователь>@<рабочая машина>
```

Проверка перед первым запуском на машине: `python -m pytest app/tests -q` (около 2 минут, процессор, без весов).

## Модели Г1: как заменить

Модель не заморожена. Интерфейс работает с контрактом `epiapp/g1/models/base.py` (`G1Model`: `available()`, `load()`, `predict(запись) → оценка,
оценки по частям записи`) и с **паспортом модели** (`card`): задача, обучение, цифры качества с указанием файла-источника, порог по
умолчанию, тексты вывода, ограничения. Новая модель — класс в `epiapp/g1/models/` и строка в `registry.py`; экраны не меняются
(проверяется тестом `test_new_model_plugs_in`).

| `EPI_G1_MODEL` | Что | Качество (источник) | Состояние |
|---|---|---|---|
| `reve_dino` | готовые REVE v4 + EEG-DINO v2, детектор ненормальной ЭЭГ | ROC AUC 0,920 NMT / 0,936 Турция / 0,756 Бангладеш (`h1_eeg/SUMMARY.md`); на TUEP 0,523 (`h1_eeg/results/tuep_improve_2026-11-15.md`) | веса есть, готова к запуску на машине |
| `tuep_pair` | REVE v4, дообученная на TUEP, + эталон (мощности, амплитуда, wPLI + лог. регрессия) | ROC AUC 0,661 (0,59–0,74) на TUEP (`h1_eeg/results/tuep_improve_2026-11-15.md`) | нужно сохранить модели: `h1_eeg/tuep/README.md`, раздел 10 |
| `demo` | формула вместо нейросети | — | только для показа |

**Порог клиники хранится отдельно для каждой модели**: оценки разных моделей несравнимы. Пока порог не настроен, действует порог модели
с открытых данных, и интерфейс прямо об этом предупреждает.

Путь расчёта совпадает с экспериментами: `reve_dino` — как `tuep_infer.py`; `tuep_pair` — как проверка по фолдам (`tuep_finetune.py`,
`tuep_baseline.py`). Общий код оценки одной записи — `h1_eeg/src/record_scoring.py`; его совпадение со скриптами экспериментов
проверяет `tests/test_tuep_final.py`. **Сами нейросети на ноутбуке не запускались** — первый запуск на рабочей машине за Захаром.

## Проверка входа ЭЭГ

Подготовка — как у общего набора Г1: 19 каналов 10–20, 200 Гц, средний референт, 0,1–75 Гц + режекция сети (функции
`h1_eeg/tuep/tuep_common.py`). Исходный EDF после подготовки удаляется, хранится только подготовленный сигнал.

| Что | Предупреждение | Оценка невозможна |
|---|---|---|
| Длительность | короче 20 мин | короче 1 мин |
| Каналы | 1–4 канала без сигнала (обнуляются, в референт не входят) | нет какого-то из 19 каналов; больше 4 без сигнала |
| Частота | ниже 200 Гц | — |
| Артефакты | от 20 % записи | — (от 50 % — красная карточка) |
| Прочее | необычный масштаб сигнала; сеть 60 Гц при режекции 50; разные ушные референты | не EDF (например, BDF) |

Артефакты определяются приближённо (размах больше 300 мкВ; высокочастотная составляющая в 4 раза выше обычной в ≥ 3 каналах) и
показываются только как показатель качества. Пороги — в начале `epiapp/g1/prepare.py`; **их стоит обсудить с врачами**.

## Настройка под клинику (Г1)

- **По размеченным записям** (около 20): порог по индексу Юдена, дополнительно — порог на чувствительность 80 %. Правила те же, что
  в экспериментах (`tuep_protocol.py`), совпадение проверяет тест. Показываются счётчики «9 из 10» и 95 % ДИ (бутстреп по записям).
- **Без разметки**: медиана оценок записей клиники (`h1_eeg/notebooks/h1_2026-11-10_zs_unlabeled-threshold.py`).
- Записи для настройки загружаются пачкой (каждая проходит ту же подготовку и ту же модель). Записи из обычной работы копятся
  автоматически без диагноза; диагноз можно проставить позже. Порог сохраняется в базе, действует после перезапуска и применяется
  ко всем записям, в том числе уже оценённым.

## Г2: контракт и что нужно от Ярославы и Дарьи

Модели Г2 живут в своих окружениях (monai + FSL; nnU-Net), поэтому приложение вызывает **внешнюю команду** и читает файлы — описание в
`epiapp/g2/contract.py`:

```
<команда> --t1 T1.nii.gz --flair FLAIR.nii.gz --out ПАПКА
ПАПКА/prob.nii.gz (обязательно) · candidates.csv · qc.json · t1.nii.gz · flair.nii.gz · brain_mask.nii.gz (желательно)
```

Контракт проверен тестом с подставной командой (`tests/test_g2.py`), **настоящие модели Г2 не запускались**.

**От Ярославы (MS-DSA-NET):**
1. Положить в репозиторий `msdsa_lib.py` (например, в `h2_mri/src/`) — в блокнотах есть только его вызовы.
2. Проверить и поправить шаблон `tools/g2_msdsa_cli.py` (места с пометкой «ПРОВЕРИТЬ»): он собран по ячейке `predict_new()`.
3. Сообщить пути на машине: проект с `deploy/` (5 весов, `config.json`, `nyul_ref_uhb.npy`), клон кода MS-DSA-NET, шаблон MNI, окружение с FSL.
4. Уточнить: в какой сетке лежит `*_prob.nii.gz` (исходный T1 или после совмещения) и где совмещённые T1 и FLAIR; сколько длится расчёт
   одного пациента (в блокноте пример шёл 286 минут — это паузы на охлаждение?).
5. Таблицу рабочих точек приложение берёт из блокнота `ms_dsa_net_stage2b_cv.ipynb`, раздел 9 (порог 0,9: очаг найден у 56 % пациентов с ФКД,
   0,13 ложных находок на человека без ФКД у ансамбля). В макете стояло «0,16» — прошу подтвердить, какая цифра верная.

**От Дарьи (nnU-Net):** проверить шаблон `tools/g2_nnunet_cli.py` (порядок каналов, тренер, фолды, нужна ли подготовка снимков как при
обучении) и дать таблицу рабочих точек (порог → находимость, ложные на человека) — паспортом в формате `EPI_G2_CARD`.

Запуск с моделью Г2: `export EPI_G2_CMD="<python окружения модели> ~/epilepsy-mvp/app/tools/g2_msdsa_cli.py"` (+ переменные `MSDSA_*`).

Просмотрщик срезов — свой, на canvas (`web/js/mri.js`): три плоскости в радиологической ориентации, перекрестие, карта вероятности,
контуры кандидатов, профиль вероятности по срезам. NiiVue не взят, чтобы не скачивать внешнюю библиотеку и работать без интернета.
Формат входа — NIfTI; папку DICOM нужно заранее преобразовать (`dcm2niix`).

## Отчёт для врача

Экран отчёта → поле «Заключение врача» → «Выдать отчёт». Сервер отказывает, если заключение пустое (тест `test_g1_upload_run_report`).
Содержимое отчёта собирает сервер из сохранённого исследования, отчёт хранится в базе. Печать и PDF — средствами браузера.

## Данные пациентов

Всё обрабатывается на машине, где запущен сервер; внешних запросов приложение не делает (с `HF_HUB_OFFLINE=1` — и модели тоже).
В базе — имя файла, код пациента (если введён), оценки, решения врача, отчёты; сигнал и снимки — в `EPI_VAR_DIR`. Каталог `app/var/`,
веса и данные в git не попадают.

## Интерфейс: «Пульт» (с 16.11.2026)

Интерфейс переделан целиком в направлении B из [docs/design/](docs/design/README.md) — тёмная рабочая станция. Макет Дарьи
остался в истории git; логика и сервер те же. Снимки экранов — [docs/screens/](docs/screens/).

**Правила оформления** (`web/css/app.css`):
- Экран не прокручивается целиком: просмотр в центре, оценка и решение врача — в правой панели, прокрутка только внутри панелей.
- Всё, что нарисовала программа (оценка, карта, контур кандидата), — янтарным; замечания к входу — коралловым.
- Состояние передаётся формой и словом (▲ замечание, ● без замечаний, ■ не подходит), не только цветом.
- Шрифты системные, внешних файлов нет — работает без интернета.

**Что поменялось и почему**

| Было | Стало | Почему |
|---|---|---|
| Главная: картинка и две плитки | Список исследований: вход, оценка программы, решение врача; справа предпросмотр | сразу видно, что ждёт врача |
| Два режима: «пошаговый» и «рабочее место» | Одна страница исследования на все состояния (проверка → расчёт → оценка → решение) | не надо выбирать путь |
| Вкладки «Г1 · ЭЭГ», «Г2 · МРТ» | Вкладки открытых исследований, как в редакторе | «Г1/Г2» — наш жаргон |
| «Спидометр» и четыре плашки одного веса | Крупное число, вывод словами, шкала 0–1 с порогом | главное — за секунду |
| Порог клиники — мелкая строка | На шкале — записи клиники с известным диагнозом и счёт «9 из 10 выше порога» | новизна на виду |
| Решение врача под сгибом, в МРТ его нет | Блок «Решение врача» закреплён внизу панели; у каждого кандидата «Очаг / Не очаг / Не уверен» | заключение по МРТ закрыто, пока кандидаты не отмечены |
| Карта вероятности закрывает срез | Четвёртое окно — «под перекрестием без карты», клавиша К снимает карту | карта не должна заслонять анатомию |
| Отчёт: форма на отдельном шаге | Слева лист отчёта, справа заключение; текст сразу виден на листе | врач видит, что именно выдаст |
| Справка о модели — раскрывающаяся строка | Экран «О моделях»: паспорта, цифры со ссылками на файлы, таблица рабочих точек | честные цифры в одном месте |

**Клавиши** (по физической клавише, раскладка не важна): `N` — новое исследование, `↑ ↓ ⏎` — список; ЭЭГ: `← →` листать,
`С` согласен, `Н` не согласен; МРТ: `1–9` кандидат, `О` очаг, `Н` не очаг, `К` карта, `↑ ↓` срезы; `⏎` — главный шаг экрана.

**Сервер** — добавлено без изменения прежних ответов: поле `report` (номер выданного отчёта) в исследованиях и списках; в списке МРТ —
`created`, `decision`; в отчёт попадает решение врача (согласие по ЭЭГ, отметки кандидатов по МРТ, `decision.marks`); новый вид
печатного листа. Тест — `test_doctor_decision_goes_to_list_and_report`.

**Доступность:** контраст текста не ниже 4,5 : 1; всё управляется с клавиатуры, виден фокус; у графиков и срезов есть текстовые подписи.

**Проверено:** в демо-режиме пройден путь ЭЭГ и МРТ до выданного отчёта, настройка под клинику, окна 1366 × 768 и 1920 × 1080.
**Не проверено:** загрузка своих файлов МРТ (в демо недоступна), перетаскивание файлов в окно, печать, окна уже 1180 px.

## Тесты

`py -m pytest app/tests -q` — 42 теста, около 2 минут на процессоре, без весов и данных:
подготовка ЭЭГ на синтетическом EDF (`test_prepare.py`), порог клиники (`test_threshold.py`), контракт моделей Г1 (`test_models.py`),
контракт Г2 с подставной командой (`test_g2.py`), сервер целиком и отчёт (`test_app.py`), итоговые модели TUEP на синтетике (`test_tuep_final.py`).

## Что не сделано

- Настоящие модели не запускались через приложение (на ноутбуке нельзя): `reve_dino` — нужен первый запуск на машине; `tuep_pair` — сначала сохранить модели.
- Г2: `msdsa_lib.py` нет; шаблоны команд не проверены.
- DICOM, вход по паролю, одновременная работа нескольких врачей (расчёты идут по очереди, по одному).
- Возраст и пол в модели не используются (в варианте `tuep_pair` — набор признаков без них).
