# План: приложение «ЭпиАссистент» (Г1 ЭЭГ + Г2 МРТ)

Дата плана: 15.11.2026. Срок приложения — 02.12.2026, предзащита ~04.12, защита 11.12.
Основа интерфейса — макет Дарьи `Приложение_концепты/Дарья/EpiAssistant_Дарья_v4.html`.

## 1. Что строим

Одно приложение: сервер на Python с моделями и интерфейс в браузере по макету Дарьи.
Два режима запуска одного и того же кода:

| Режим | Где | Модели | Данные |
|---|---|---|---|
| **демо** | ноутбук, без видеокарты | демо-модели (пометка «ДЕМО») | синтетические записи и снимки, создаются на лету |
| **боевой** | рабочая машина (Ubuntu, RTX A5000) | настоящие модели Г1; Г2 — через внешнюю команду | файлы врача, остаются на машине |

В демо-режиме работает весь настоящий путь, кроме самих нейросетей: чтение EDF, подготовка, проверка входа, порог клиники,
просмотр сигнала и срезов, отчёт. Это позволяет проверять приложение на ноутбуке и показывать его без моделей.

## 2. Стек и почему

- **Сервер: FastAPI + uvicorn.** Нужны: загрузка больших файлов, фоновые расчёты с ходом выполнения, отдача кусков сигнала и
  объёмов МРТ. Streamlit для листания сигнала и срезов не подходит (отмечено в `Концепты.md`).
- **Интерфейс: HTML + CSS + JavaScript без сборки** (ES-модули). Стили, тексты и рисование берутся из макета Дарьи почти без
  изменений; сборщики и внешние библиотеки не нужны, приложение работает без интернета.
- **Хранилище: SQLite** (встроен в Python): исследования, записи клиники, пороги, отчёты. Отдельного сервера БД нет.
- **ЭЭГ:** numpy + scipy; чтение EDF — функции из `h1_eeg/tuep/tuep_common.py` (без mne).
- **МРТ:** nibabel (чтение NIfTI) + scipy.ndimage. **Просмотрщик срезов свой, на canvas**, а не NiiVue: NiiVue потребовал бы
  скачивать внешнюю библиотеку (~1,5 МБ) и WebGL2; свой просмотрщик на 3 плоскости — около 300 строк, работает без интернета,
  оформляется как в макете (перекрестие, контуры кандидатов, подписи П/Л). NiiVue можно подключить позже — данные отдаются
  как обычные объёмы.
- **Отчёт:** страница для печати, PDF — через печать браузера (как в макете). Отчёт выдаёт сервер и только с заключением врача.

## 3. Устройство

```
app/
  epiapp/
    __main__.py        запуск: py -m epiapp --demo | --real
    config.py          настройки (переменные окружения EPI_*)
    server.py          FastAPI: маршруты
    jobs.py            очередь расчётов (один поток — одна видеокарта), этапы и ход
    store.py           SQLite
    report.py          выдача и страница отчёта
    g1/  edf.py, prepare.py (подготовка + проверка входа), synth.py (синтетическая ЭЭГ и запись EDF),
         threshold.py (порог клиники), models/ (контракт и реализации)
    g2/  contract.py, volume.py (NIfTI → общая сетка для просмотра), candidates.py (кластеры),
         phantom.py (синтетические «снимки»), adapters/ (демо, внешняя команда)
  web/                 интерфейс (index.html, css/, js/)
  tools/               шаблоны команд Г2 (MS-DSA-NET, nnU-Net)
  tests/
  docs/screens/        снимки экранов
```

Код Г1 не копируется: приложение подключает `h1_eeg/tuep/tuep_common.py`, `h1_eeg/src/shared_data.py` и новый лёгкий модуль
`h1_eeg/src/record_scoring.py` (окна, сборка оценки, признаки эталона — только numpy/scipy). Совпадение нового модуля с
`tuep_finetune.py` / `tuep_baseline.py` проверяется тестом на синтетике.

## 4. Контракты моделей

### Г1 — `epiapp/g1/models/base.py`

```python
class G1Model:
    id: str; title: str
    card: dict        # чему обучена, метрики со ссылкой на файл результатов, порог по умолчанию и его источник,
                      # тексты вывода «выше / ниже порога», ограничения
    def available(self) -> tuple[bool, str]     # есть ли веса и библиотеки; иначе причина
    def load(self) -> None                      # один раз, перед первым расчётом
    def predict(self, rec: PreparedRecord, progress) -> G1Output
# PreparedRecord: x (19, n) float32, мкВ, 200 Гц, порядок каналов EL, средний референт, 0,1–75 Гц + режекция сети
# G1Output: score 0..1 (вся запись), parts [(t0, t1, score)] — оценки по частям записи (устойчивость),
#           components {имя: оценка}, n_windows, seconds
```

Реализации:

| id | Что | Состояние |
|---|---|---|
| `demo` | демо-модель: оценка из простых свойств сигнала, без клинического смысла | работает везде |
| `reve_dino` | готовые REVE v4 + EEG-DINO v2 (по 3 запуска), путь как в `tuep_infer.py` | веса есть |
| `tuep_pair` | REVE v4, дообученная на TUEP, + эталон (мощности, амплитуда, wPLI + лог. регрессия) | веса надо сохранить (п. 6) |

Модель выбирается настройкой `EPI_G1_MODEL`; интерфейс от модели не зависит. **Порог клиники хранится отдельно для каждой
модели**: оценки разных моделей несравнимы, при смене модели порог настраивается заново.

### Г2 — внешняя команда + файлы (`epiapp/g2/contract.py`)

У Ярославы и Дарьи свои окружения (monai, FSL, nnU-Net), у приложения — своё. Поэтому контракт — команда и файлы, а не
импорт кода:

```
<команда> --t1 T1.nii.gz --flair FLAIR.nii.gz --out ПАПКА
ПАПКА/prob.nii.gz        карта вероятности 0..1
ПАПКА/candidates.csv     peak_prob, volume_ml, x, y, z   (мм, мировые координаты карты)
ПАПКА/qc.json            {"t1_mm":…, "flair_mm":…, "mni_corr":…, "flags":[…], "ok":true}
ПАПКА/t1.nii.gz, flair.nii.gz, brain_mask.nii.gz   (необязательно: снимки в сетке карты)
```

Адаптеры: `demo` (синтетические снимки и карта), `external` (любая команда по контракту). Шаблоны команд:
`tools/g2_msdsa_cli.py` (по ячейке `predict_new()` блокнота `ms_dsa_net_stage2b_cv.ipynb`) и `tools/g2_nnunet_cli.py`.
Проверка входа (размер вокселя T1 и FLAIR, предупреждение о FLAIR ≥ 5 мм) делается приложением до запуска по заголовкам NIfTI.

## 5. Экраны (по макету Дарьи)

Главная → выбор ЭЭГ / МРТ → рабочее место или пошаговый режим (загрузка → проверка → расчёт → результат → отчёт);
«Настройка под клинику»; отчёт для врача. Отличия от макета — только там, где он расходится с настоящими данными;
все они перечислены в README (раздел «Что изменено в дизайне»).

## 6. Сохранение моделей варианта (б) — для рабочей машины

- `tuep_finetune.py final` — обучение REVE v4 на всех пациентах TUEP, число эпох фиксировано (медиана лучших эпох по фолдам),
  3 запуска → `final/reve_tuep_seed{0,1,2}.pt`.
- `tuep_baseline.py --save-model` — эталон на всех пациентах, C — как чаще всего выбиралось в фолдах → `final/baseline_bpampw.npz`
  (только массивы: приложению не нужен sklearn).
- `tuep_finetune.py card` — паспорт пары: ROC AUC и пороги (Юден, чувствительность 80 %) по оценкам вне обучения → `final/pair_card.json`.
- Все три проверяются на синтетике игрушечной сетью; на настоящих данных запускает Захар.

## 7. Этапы

| № | Этап | Проверка |
|---|---|---|
| 1 | Каркас: сервер, настройки, хранилище, очередь, главная страница | сервер поднимается, главная как в макете |
| 2 | Г1: чтение EDF, подготовка, проверка входа, синтетика | тесты на синтетическом EDF |
| 3 | Г1: контракт модели, демо-модель, расчёт, результат, пошаговый режим | путь загрузка → результат в браузере |
| 4 | Г1: порог клиники (20 размеченных, без разметки), хранение и применение | тесты порога, экран настройки |
| 5 | Г1: рабочее место (листание сигнала, монтажи, шкала времени) | в браузере |
| 6 | Г2: синтетические снимки, контракт, кандидаты, просмотрщик 3 плоскостей, пошаговый режим и рабочее место | тесты контракта, в браузере |
| 7 | Отчёт для врача (заключение обязательно), печать | тест отчёта |
| 8 | Настоящие модели Г1 (`reve_dino`, `tuep_pair`), сохранение моделей TUEP | тесты на синтетике; запуск — на рабочей машине |
| 9 | Шаблоны команд Г2, README, снимки экранов | — |

## 8. Риски

| Риск | Что делаем |
|---|---|
| Модель Г1 не выбрана | подключаемый контракт; порог — по модели; тексты вывода — из паспорта модели |
| Вариант (а) на TUEP — на уровне случайного (0,52), вариант (б) — 0,66 | в паспорте модели и в «Справке о модели» честные цифры со ссылкой на файл результатов |
| `msdsa_lib.py` нет в репозитории | контракт «команда + файлы», шаблон команды, список для Ярославы |
| Настоящие модели нельзя проверить на ноутбуке | проверка формы входа и сборки оценки на синтетике; первый запуск на машине — по командам из README |
| EDF клиник отличаются от TUH (имена каналов, референт, частота) | терпимый разбор имён, проверка входа с понятными сообщениями; режекция 50 Гц по умолчанию |
| Данные пациентов | всё локально, каталог данных вне git, в журнал и отчёт не пишется сигнал |
| Данные TUH | в демо не используются: демо — синтетика |
